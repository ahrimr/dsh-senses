# dsh-senses

> **陪你看视频的 AI —— 你看到哪，它就知道到哪。**
> 实时、不剧透、不下载视频。Windows 上的 DeepSeek Harness 插件。

---

## 它在陪你，不是在解说

大多数"AI 看视频"是**看完再总结**：整段视频或整份字幕一次性喂给模型，让它概括。

那是解说，不是陪伴 —— **而且它一定会剧透**。

dsh-senses 走的是另一条路：

```
你在看第 4 分钟
   ↓
我知道你在看什么、播到第几秒
   ↓
我只拿到「你已经看过的这 4 分钟」的字幕
   ↓
第 4 分钟之后的字，我一个字都没有
```

**所以你能问它「刚才这段什么意思」，但它没办法告诉你「后面谁死了」。**

---

## 「实时」是数出来的

| 动作 | 耗时 |
|---|---|
| 问「现在在播什么、播到哪」 | **0.6 秒** |
| 问「刚才那 90 秒讲了什么」 | 冷 **1–2 秒** / 热 **0.1 秒** |
| 暂停 / 拖进度 / 下一集 | 动作后会**复核状态**再回报 |

**为什么这么快**：它不下载视频，只取**字幕 JSON**（几十到几百 KB），并按 `视频 ID + 分P + 语言轨` 缓存。
第二次问同一部片，**0 网络请求**。

---

## 它为什么敢说「不剧透」

不是靠自觉，是**机制**：

```js
窗口 = [t - back, t]          // t = 你现在播到的秒数
跨过 t 的那一条字幕 → 整条丢弃   // 不按比例截断
返回里带 droppedAfterT         // 丢了多少行，模型看得见
```

为什么不按比例截断：一条字幕里，文字和它内部的时间**不是线性对应** ——
截一半等于把后半句的意思提前泄露出去。

**所以模型连"提示"都拿不到。**

## 四个工具

| 工具 | 干什么 | 约耗时 |
|---|---|---|
| `senses_media` | 谁在播 / 在播什么 / 播到第几秒 / 是播是停 / 刚才在看什么 | **0.6 秒** |
| `senses_media_control` | 暂停 / 继续 / 拖进度条 / 上一集 / 下一集（**每次动作都复核状态**） | — |
| `senses_watch` | 读某个视频在某个时间段的**字幕原文**，只给 `t` 之前 | 冷 1–2 秒 / 热 **0.1 秒** |
| `senses_browse` | 驱动一个**受控** Edge：开页 / 读正文 / 点 / 滚 / 截图 | 0.5–2 秒 |

---

## 三道闸：为什么"拿到了"不等于"拿对了"

B站 的 `player/v2` 会**间歇性返回别的视频的字幕 URL** ——
实测同一视频连取 10 次，只有 3 次是对的。**错的那些读起来完全正常**：不报错、不异常，就是别人的台词。

所以它有三道闸：

| 闸 | 挡什么 |
|---|---|
| **跨度闸** | 正文跨度必须和视频时长对得上（挡掉 225 秒 / 1716 秒那种别人家的字幕） |
| **一致性闸** | 同一请求最多 6 次取样，两次 hash 一致才认 |
| **语义闸** | 标题里的英文词 / 数字 / 中文双字组，至少要命中（挡"错得稳定"的串号） |

**取向：宁可真失败，也不给一份假的。**

## 安装

插件是 **Host 级的一条 bundle 行**，装进去以后**每个 agent 预设都继承得到**，不用给每个模式拷预设。

```bash
# 在 DSH 里
plugin_manager install_bundle  dsh-senses
```

或者手动在 profile 的 `cordis.patch.yml` 里加：

```yaml
- insert:
    - id: senses
      name: dsh-senses
```

**不需要配 `root`** —— 插件会用自己的包根目录。

### 前置

| 依赖 | 必须吗 | 说明 |
|---|---|---|
| **Windows** | ✅ | 媒体会话走 SMTC，浏览器驱动走 CDP |
| **PowerShell 5.1** | ✅ | 系统自带。**含中文的 .ps1 必须有 BOM**，否则 PS 5.1 会解析崩溃 |
| **Node ≥ 22** | ✅ | 插件宿主就是 Node |
| B站 登录 | 字幕/浏览要 | 用一个**专用 profile** 的 Edge 扫码登录一次（不碰你日常浏览器） |

## 红线（写进代码，不是写在文档里）

1. **不抢键鼠和前台。** 指针锁只在一次动作的几秒内存在。
2. **写操作必须先被要求。** 暂停/继续/拖进度是**改用户在播的东西** —— 只在你明确说要的时候做。
3. **绝不猜目标。** 同时在播多个又没给标题 → 直接拒绝（`exit 4`）。
4. **「停手」是 fail-closed 闸门。** 标志在，连目标都不查就退回（`exit 6`）。
5. **不读源码、不改内存、不注入别人的进程。** 器官住在包里。

---

## 已知限制（真实现状，不粉饰）

| 限制 | 说明 |
|---|---|
| **同一个程序的多个窗口分不清** | 系统只给 `SourceAppUserModelId`，没有窗口身份。实测同一个 Edge 开直播+视频，只报"当前那个标签页"，另一个**整个消失且不报错** |
| 改播放速率 | 不可用 —— `Controls` 报 `IsPlaybackRateEnabled=False`，浏览器不暴露 |
| B站 字幕的准确性 | 字幕由平台/上传者提供，**未经校验**。AI 字幕的人名、梗经常错 |
| 覆盖率 ≠ 正确 | 返回里的覆盖率是"时间区间被字幕覆盖的比例"，**不是语义完整，也不是正确** |

## 目录

```
plugin/index.mjs      插件入口（注册四个工具）
adapters/
  media.ps1           读系统媒体会话 + 控制播放（PowerShell，SMTC）
  subtitle.mjs        取字幕 + 三道闸 + 按视频身份缓存
  watch.mjs           陪看一次调用：按需起浏览器 → 切片 → 用完关掉
  browse.mjs          驱动受控 Edge（pages/open/read/click/scroll/shot）
  bili-login.mjs      从受控 Edge 读登录 cookie / 校验登录态
  serve.mjs           带 Range 的静态服务（测试台用）
bili-browser.ps1      受控 Edge 的启停管理
bundle/               挂载层（一条 patch 行）
test/plugin-selftest.mjs   离线自测（不碰网络、不碰真实浏览器）
```

跑自测：

```bash
node test/plugin-selftest.mjs
# PASS 插件闸门（48 项）
```
